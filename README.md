# Hermes BNN Intake 0.14.2

Подключаемый процесс смысловой подготовки информации для совместимой Hermes BNN: уточнение задачи, раскрытие материала, атомарная декомпозиция, выбор методов, восполнение лакун, работа с документами, наследование ограничений и системная приёмка.

- [Архитектура и границы](docs/ARCHITECTURE.md).
- [Проверки и ограничения](docs/VERIFICATION.md).
- [Точные схемы семи инструментов](docs/TOOL_CATALOG.json).
- [Реестр 120 требований](docs/REQUIREMENTS.json).
- [Архив исходников и установочного комплекта](archives/Hermes-Intake-0.14.2.zip).
- [Контрольные суммы](SHA256SUMS).

Это расширение существующей платформы. Оно не содержит ядро Hermes, подписанные GSD/UDR/Foundation, Beads, Dolt, среды разбора документов, базы памяти, пользовательские профили, ключи, OAuth или личность агента. Обычная установка Hermes без требуемых интерфейсов не становится совместимой только после установки этого wheel.

Проверенная основа: Memory `2.0.0-dev.43`, ядро commit `d923a5eb487a17c0a68801bba9ef0f56c81040a8`; точные хеши находятся в `src/bnn_intake/data/native-compatibility.json`. Новая неизвестная основа требует отдельной проверки интерфейсов. Подмена хешей для обхода несовместимости не является интеграцией.

Код `src/bnn_intake` совпадает с установочным wheel по байтам. Тесты используют собственные временные пространства. Для воспроизведения полного набора нужна подготовленная совместимая платформа; её путь задаётся через `HERMES_INTAKE_NATIVE_ROOT`. Тесты не заменяют отсутствующего исполнителя успешным результатом.

Режимы: `/intake off`, `/intake auto`, `/intake on`. Новые беседы начинают с `off`. Общая политика автономной системной приёмки сохраняется при отключённом Intake: необходимые доступные проверки выполняет система, рекомендации аналитику не блокируют выпуск.

Открытый и закрытый репозитории содержат один и тот же обезличенный комплект; различается доступ. История разработки и материалы конкретного владельца в них не переносятся. Лицензия на исходный код этим комплектом не назначается.
