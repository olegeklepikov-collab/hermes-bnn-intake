# Интеграция Hermes BNN Intake 0.14.4

## 1. Область установки

Инструкция подключает Intake к уже установленной совместимой нативной Hermes BNN. Она не разворачивает всю платформу с нуля и не выдаёт произвольный upstream Hermes за проверенную основу.

Состав: исходный код, wheel, проверяющий установщик, точные схемы инструментов, каталог методов, тесты, манифесты, небольшой патч старых средств обслуживания и эта инструкция. Базы, исследовательские корпуса, учётные данные, личность, архивы старого владельца и внешние программы отсутствуют.

Связанные проекты: [публичная поставка Hermes BN](https://github.com/olegeklepikov-collab/hermes-bn-gsd-udr-public), [Hermes UDR](https://github.com/olegeklepikov-collab/hermes-udr). Эти ссылки не означают, что любой их выпуск автоматически совместим с Intake 0.14.4. Сначала сопоставьте точные версии и контрольные суммы.

## 2. Необходимая основа

| Компонент | Требование |
|---|---|
| ОС | Квалификация выполнена на macOS Apple Silicon; другие ОС и архитектуры отдельно не приняты |
| Python | Метаданные пакета требуют 3.11+; использовать собственную среду Python установленной Hermes, в которой доступны `jsonschema` и `PyYAML` |
| Hermes | Commit `d923a5eb487a17c0a68801bba9ef0f56c81040a8` и точные закреплённые файлы интерфейсов |
| Общая память | `2.0.0-dev.45`, существующий `bn_memory.Store`, основной `memory.sqlite`, настройки и собственный ключ подписи |
| Основная работа | Родная рабочая карточка и Beads; второй главный граф задач не создаётся |
| Документы | Штатные `Documents`, изолированные исполнители разбора и среды нужных форматов, если требуется документарная работа |
| GSD | Согласованный установленный SDK и нативные роли для маршрутов G/S/D; не нужен для простого отключения Intake |
| UDR/Foundation | Согласованная пара Research/Foundation и собственный Dolt для исследовательских назначений и квитанций |
| Авторизация | Собственные доступы владельца; они настраиваются отдельно и не берутся из архива |

При отсутствии GSD или UDR не объявляйте их путь работающим. Отключённый optional-модуль не должен закрывать допустимую базовую работу. Обязательный контроль защищённого действия при неисправности закрывает только зависимый путь.

Владелец должен иметь собственные `profile_home`, `state_root`, `host_key`, проекты и подготовленные настройки общей памяти. Эти изменяемые пути и изменяемое состояние подключённых модулей должны находиться внутри выбранного управляемого корня. Ключи, данные или рабочие каталоги другого пользователя не подставляются.

## 3. Получить и проверить именно полный комплект

Эта редакция 0.14.4 поставляется внутри полной платформы Memory dev.44. Используйте полный выпуск `hermes-bnn-full` либо `hermes-bnn-full-private`, затем его `install.sh`. Отдельные репозитории `hermes-bnn-intake` версии 0.14.4 относятся к предшествующей основе dev.43 и не являются источником байтов этой парной редакции.

После распаковки из полного архива исходный каталог находится в `Hermes-BNN-Full/Intake`. Для отдельной проверки из этого каталога:

```sh
../Hermes/runtime/python/cpython-3.14.6-macos-aarch64-none/bin/python3.14 tools/verify_package.py
shasum -a 256 -c PAYLOAD-SHA256SUMS
```

Здесь нет отдельного отсутствующего ZIP Intake: он уже входит в полный архив. `PACKAGE-MANIFEST.json` и `packages/manifest.json` относятся к текущим файлам. Свидетельства предшествующей версии явно отделены в `provenance`. Хеши не являются внешней подписью; происхождение указано в `PROVENANCE.json`.

## 4. Задать собственные пути

Замените примеры настоящими абсолютными путями. Не используйте буквально строки `/полный/путь/...`.

```sh
HERMES_INTAKE_REPO="$(pwd)"
HERMES_INTAKE_ROOT='/полный/путь/к/собственному/Hermes-BNN'
HERMES_INTAKE_CONFIG="$HERMES_INTAKE_ROOT/Memory/settings.json"
HERMES_INTAKE_PROFILE="$HERMES_INTAKE_ROOT/data"
HERMES_INTAKE_CORE="$HERMES_INTAKE_ROOT/hermes-agent"
HERMES_INTAKE_MEMORY="$HERMES_INTAKE_ROOT/Memory/releases/2.0.0-dev.45"
HERMES_INTAKE_PYTHON="$HERMES_INTAKE_CORE/venv/bin/python"
HERMES_INTAKE_LIB="$HERMES_INTAKE_ROOT/Intake/0.14.4"
HERMES_INTAKE_WHEEL="$HERMES_INTAKE_REPO/packages/hermes_bnn_intake-0.14.4-py3-none-any.whl"
```

Если профиль или настройки лежат иначе, возьмите значения из своей установленной конфигурации. `HERMES_INTAKE_PROFILE` должен точно совпадать с её `profile_home`. Каталог библиотеки должен быть новым: установщик не затирает существующие файлы.

## 5. Проверить совместимость до изменений

```sh
"$HERMES_INTAKE_PYTHON" "$HERMES_INTAKE_REPO/tools/check_compatibility.py" \
  --root "$HERMES_INTAKE_ROOT" --config "$HERMES_INTAKE_CONFIG"
```

Это чтение, без Host, миграции, обновления токенов и модельного вызова. Проверяются закреплённые файлы ядра и памяти, область изменяемых путей и единственный каталог плагина общей памяти. При `Unsupported dependency`, неизвестной структуре модулей или неоднозначном плагине остановите установку. Изучите несовместимость; не отключайте контроль и не пересчитывайте хеши вместо квалификации.

## 6. Подготовить владельца команд и остановить собственный профиль

Для Telegram и иных шлюзов `command_owners` в настройках общей памяти должен содержать строковые идентификаторы именно вашего владельца. Например, значение `YOUR_TELEGRAM_USER_ID` заменяется вашим числовым ID, записанным строкой. Это не имя бота и не токен. Не копируйте идентификаторы прежнего владельца. Такой параметр согласуется до установки, чтобы он вошёл в проверяемую конфигурацию.

Остановите только выбранный профиль и его исполнителей штатным средством вашей поставки. Для поставки с оболочкой BNN обычно:

```sh
"$HERMES_INTAKE_ROOT/bin/hermes" gateway stop
```

Для установки, управляемой штатной службой ядра, используется её собственный `gateway stop` с явным `HERMES_HOME`. Сначала убедитесь, что команда относится к выбранному профилю. Не используйте `--all`, принудительное завершение или чужие службы.

Дождитесь остановки собственных модельных, дочерних и модульных записывающих процессов. Штатно сохраните либо приостановите активную работу; остановка процесса не означает успеха незавершённой задачи. Неизвестные расходы и эффекты сохраняются. `offline_attested=True` ниже означает реальное подтверждение остановки, а не способ обойти её проверку.

## 7. Установить проверенную библиотеку

Установщик работает без pip и не выполняет setup.py. Используйте фактический SHA-256 из `packages/manifest.json`:

```sh
HERMES_INTAKE_WHEEL_SHA256='7df170543e6f8acfcf2c275e9b31e44943f01871006ee36a1b92f8103807646f'
mkdir -p "$HERMES_INTAKE_ROOT/Intake"
"$HERMES_INTAKE_PYTHON" "$HERMES_INTAKE_REPO/packages/unpack.py" \
  --wheel "$HERMES_INTAKE_WHEEL" \
  --expected-sha256 "$HERMES_INTAKE_WHEEL_SHA256" \
  --target "$HERMES_INTAKE_LIB"
```

Для установочного процесса:

```sh
export HERMES_HOME="$HERMES_INTAKE_PROFILE"
export PYTHONPATH="$HERMES_INTAKE_LIB:$HERMES_INTAKE_MEMORY:$HERMES_INTAKE_CORE"
export PYTHONDONTWRITEBYTECODE=1
"$HERMES_INTAKE_PYTHON" -c 'import bnn_intake; print(bnn_intake.__version__, bnn_intake.__file__)'
```

Ожидаются `0.14.4` и путь внутри установленной библиотеки, без импорта из `src` другой копии.

## 8. Подключить к существующему Host

Для существующего большого окружения предпочтителен узкий установочный резерв:

```sh
"$HERMES_INTAKE_PYTHON" - "$HERMES_INTAKE_ROOT" "$HERMES_INTAKE_CONFIG" "$HERMES_INTAKE_LIB" <<'PY'
import json, sys
from bnn_intake.deployment import install
receipt = install(sys.argv[1], sys.argv[2], library=sys.argv[3],
                  backup_scope='activation', offline_attested=True)
print(json.dumps(receipt, ensure_ascii=False, indent=2))
PY
```

Сохраните полный ответ локально, вне публичного репозитория, особенно:

- `before_install_snapshot.path`;
- `before_install_snapshot.manifest_sha256`;
- `common_plugin_directory`;
- сведения о миграции и развёртывании.

Фактические изменения: добавочные таблицы в существующей `memory.sqlite`, точные правила действий, профильная запись установленной библиотеки, композиционный вход прежнего плагина, файл общей политики и сертификат привязки. Второй основной Store и второй главный реестр задач не создаются.

Если каталог уже называется `bnn-common-memory`, он сохраняется. Второй `bn-common-memory` рядом не создаётся. Два одноимённых плагина либо неопознанный занятый каталог отклоняются до изменения. Пять обязательных контроллеров сохраняются.

Непустые списки инструментов получают `bnn_intake`; явно пустые списки не включаются молча. Исходный JSON/YAML-формат сохраняется установщиком. Загрузчик сам добавляет установленную библиотеку и память в путь импорта; постоянная правка общей среды Python не требуется.

Узкий резерв включает прежние конфигурационные файлы и согласованную SQLite-копию. Он не копирует программы, отдельные ключи или личность и не заменяет полный резерв платформы. Он приватный: база и настройки могут содержать данные владельца.

## 9. Проверить запуск и реальные команды

Запустите только выбранный профиль штатной оболочкой. Для поставки BNN:

```sh
"$HERMES_INTAKE_ROOT/bin/hermes" gateway run
```

Не выполняйте повторную настройку всех старых волн либо замену текущих SDK ради запуска расширения. В новом процессе проверьте обнаружение плагина:

```sh
HERMES_HOME="$HERMES_INTAKE_PROFILE" \
  "$HERMES_INTAKE_PYTHON" -m hermes_cli.main plugins list
```

Плагин общей памяти должен быть один, без ошибок регистрации. Наличие команды не доказывает наличие входа в модель, доступность всех сервисов либо завершённость исследования.

В своей настоящей беседе выполните отдельно и дождитесь каждого ответа:

```text
/intake status
/gsd status
/udr status
```

Проверьте собственные режимы. Новая беседа начинает с Intake off; прежние режимы не сбрасываются. Для адресной автоматической подготовки:

```text
/intake auto
```

`on` сохраняет явное включение, `off` убирает смысловую подготовку. Ограничения владельца и общая политика системной приёмки сохраняются. GSD и UDR/Foundation имеют собственные переключатели: их отключение не требует выключать базовую BNN или общий контроль.

## 10. Использование в работе и субагентах

Точные текущие аргументы читайте через штатный `tool_describe`; в одном запросе не более десяти имён. Полные схемы версии находятся в `docs/TOOL_CATALOG.json`.

1. Привяжите работу штатным механизмом Hermes/Beads. В `intake_work.prepare` задайте цель, результат, предмет, объект, область, период, единицы, профиль, ограничения и критерии достаточности. Не создавайте конкурирующий главный реестр задач.
2. Создайте экспозицию с источниками и зависимостями. Используются версии `record`, единицы `document_unit` и настоящие результаты `research_result`. План чтения, разбор и доставка модели имеют разные статусы.
3. Выберите подходящие методы открытого каталога через `intake_methods`. Каталог не закрывает право предложить другой метод с обоснованным паспортом. Декомпозиция может сочетать предметную, концептуальную, причинную, процессную и уровневую трассы.
4. Если нужны ответы владельца, `intake_questions` соблюдает его отказ, паузу, остановку, лимит и запрет тем. Отказ не создаёт фактов и не снимает обязанность доступного независимого исследования. Возобновлять опрос вопреки ограничению нельзя.
5. Через `intake_documents` привяжите корпус, раскройте состав, разбейте адресные чтения и проверьте покрытие. Ни поисковый отрывок, ни краткое изложение не засчитываются как чтение всего документа.
6. Через `intake_analysis` закрепите применение метода и получите продукт от настоящего модельного исполнения. Структурная корректность, фактическое происхождение и научная обоснованность различаются.
7. Для детей используйте `intake_delegation`: назначение конкретной роли и нативной задаче, профиль, источники, ограничения и обязательные зависимости передаются в подписанном контексте. Родительские разрешения не расширяются автоматически. Результат читается по настоящей квитанции и версии, включая последующее продолжение.
8. Для GSD сохраняются семь канонических сочетаний G, S, D, GS, GD, SD, GSD. Intake готовит адресный вход; исходники и логика ролей исполняются родным GSD. Повтор одной завершённой цели не превращается в рекурсивный запуск.
9. Для UDR сначала свяжите реальную активную работу, сохраните и прочитайте основание в Foundation, затем планируйте настоящие исследовательские назначения. Состояние не сводится к истории чата и может быть прочитано спустя время при сохранённых правах и версиях.

Переполнение разрешается разбиением работы с сохранением обязательного ядра и замыкания зависимостей. Отсечение обязательного контекста либо расширение разрешений не является допустимым исправлением переполнения.

## 11. Профили и окончательная приёмка

Шесть профилей: eMVP, MVP, Standard, eStandard, High Stakes, Critical Infrastructure. Новые работы получают `BNNIntakeProfileV2`; действительные исторические V1 продолжают читаться без переписывания исходных продуктов. Имя профиля не назначает автоматически уровень свидетельств E0–E5 UDR.

Система выполняет необходимые доступные проверки и завершает приёмку без ожидания внешнего человеческого ревью. Рекомендации аналитику содержат аспект, приоритет, причину и основания; они не блокируют выпуск. Неизвестное исполнение, отсутствие результата, потеря источника или невыполненная доступная проверка не превращаются в успех.

Порядок в привязанной работе:

1. Проверить фактические исследовательские пути и лакуны через `intake_research.review_path` и `review_gap` с подлинными квитанциями.
2. Выполнить `intake_work.assess` с текущей ревизией, результатами проверок и явным остатком. `limited` может завершить системную приёмку как `accepted_with_limitations`.
3. Прочитать `acceptance_status` и `acceptance_report`; проверить окончательный файл и его хеш.
4. Для связанного активного UDR выполнить `intake_delegation.publish_acceptance`, затем `finish_research` с устойчивым request_id и настоящим отчётом.
5. Повторно прочитать сохранённый результат. Если завершение прервалось после записи файла, сначала проверить эффекты и использовать штатный `udr_workspace.recover_finish` с точными прежними идентификаторами и хешами. Не подставлять новый текст для повтора.

Метки `unreviewed` и `scientific_acceptance=false` сохраняют смысл свидетельств и не означают ожидание обязательного человека. Системная приёмка не выдаёт разрешения на оплату, удаление, публичную публикацию или отправку сообщения. Недоступный материал отражается ограничением, а новая существенная вводная требует новой версии и новой приёмки.

В локальном отчёте без HTTP-библиографии Research может сохранить `partial` и `structural_citation_check=incomplete`. Не добавляйте выдуманный URL ради смены флага; сохраните ограничение и различайте его с завершением доступной системной работы.

## 12. Ограничение и остановка опроса

Команды выполняются владельцем в текущей беседе:

```text
/intake interview status
/intake interview pause
/intake interview stop
/intake interview resume
/intake interview limit --max-questions 3
/intake interview limit --blocked-topic TOPIC
/intake interview limit --until 2027-01-01T00:00:00Z
```

`TOPIC` замените собственной меткой темы; срок приведён как пример. Удаление лимита требует явной команды владельца: значение `none`, а для тем `--clear-blocked-topics`. Модель не получает право отправлять себе эти команды. Ограничение вопросов не создаёт разрешения получать запрещённые данные другим путём.

## 13. Отключить загрузку Intake

После остановки собственного профиля:

```sh
"$HERMES_INTAKE_PYTHON" - "$HERMES_INTAKE_ROOT" "$HERMES_INTAKE_CONFIG" <<'PY'
import json, sys
from bnn_intake.deployment import set_enabled
print(json.dumps(set_enabled(sys.argv[1], sys.argv[2], False,
                             offline_attested=True), ensure_ascii=False))
PY
```

При следующем запуске самодостаточный загрузчик общей политики использует тот же нативный Host без импорта optional-пакета. Данные Intake остаются. Для возврата используйте `True` и установленную библиотеку с правильным сертификатом. Изменение настроек требует явной новой привязки `enroll` после проверки, а не удаления проверки подписи.

## 14. Откат конфигурации

Сначала остановите профиль. Подставьте путь и SHA именно установочного резерва, выданные на шаге 8:

```sh
HERMES_INTAKE_CHECKPOINT='/путь/из/before_install_snapshot/path'
HERMES_INTAKE_CHECKPOINT_SHA256='хеш_манифеста_из_квитанции'
"$HERMES_INTAKE_PYTHON" - "$HERMES_INTAKE_ROOT" "$HERMES_INTAKE_CONFIG" \
  "$HERMES_INTAKE_CHECKPOINT" "$HERMES_INTAKE_CHECKPOINT_SHA256" <<'PY'
import json, sys
from bnn_intake.activation import rollback
print(json.dumps(rollback(*sys.argv[1:5], offline_attested=True),
                 ensure_ascii=False, indent=2))
PY
```

Это откат конфигурации, с сохранением текущей базы и последующей работы. Текущие файлы удерживаются в `_retained`. Последующие изменения настроек, включая сохранённую самим Hermes отметку показанной подсказки, вызывают отказ до замены: сначала требуется адресно сопоставить реальное изменение. Не стирайте чужую новую настройку ради совпадения хеша.

Незапечатанный резерв после прерванной установки не выдаётся за подтверждённый автоматический откат. Сначала сопоставьте сохранённые исходные файлы и фактические эффекты. Команда полного `restore` не принимает установочный резерв другого контракта.

Полные `snapshot`/`restore` относятся к небольшому управляемому профилю на прежних путях. Они не подтверждают потерю диска, перенос произвольного большого окружения, восстановление внешних сервисов либо identity. Для корня со всеми программами не используйте полный управляемый снимок как замену подходящему резерву платформы: он может встретить символические ссылки и лишний объём.

## 15. Проверки на своей установке

Полный локальный набор требует Beads, Dolt, GSD/UDR/Foundation, изолированного разбора документов и закреплённой нативной основы. Он использует новые временные состояния, без модели и внешнего поиска:

```sh
export HERMES_INTAKE_NATIVE_ROOT="$HERMES_INTAKE_ROOT"
"$HERMES_INTAKE_PYTHON" "$HERMES_INTAKE_REPO/tools/run_native_tests.py"
```

Отчёты `.test-output` и состояние `.test-state` остаются локальными и исключены из Git. Отсутствующая зависимость должна дать отказ, а не положительную пустую проверку. Изоляционные тесты не запускайте из папки рабочей базы.

После локального набора владелец отдельно подтверждает своё действующее подключение к модели, читает настоящий назначенный источник, получает продукт, завершает системную приёмку, повторно читает результат и проверяет реальный канал доставки. Наличие плагина, HTTP 200 или успешный синтетический callback не заменяет эти действия.

## 16. Диагностика

| Симптом | Следующее действие |
|---|---|
| Несовпадение нативных хешей | Проверить выпуск и интерфейсы; не подменять подписи |
| `module_command_owner_required` | Проверить собственный ID в `command_owners` и правильный профиль |
| Нет нативной беседы | Создать настоящую беседу и повторить команду состояния |
| Инструменты есть на диске, но не видны | Новый процесс, единственный плагин, правильная библиотека и список инструментов канала |
| Истёк OAuth/HTTP 401 | Восстановить своё подключение; режим Intake не обновляет авторизацию |
| Неизвестный исход/незавершённая запись | Проверить реальные эффекты и квитанции; не повторять автоматически |
| Переполнение | Разбить адресные экспозиции и назначения с обязательными зависимостями |
| Прежний помощник читает config.yaml только как JSON | Сохранить оригинал; проверить приложенный патч `packages/native-maintenance-config-readers.patch`. Он касается старых помощников, не SDK |
| Отказ отката после изменения настроек | Сопоставить новую настройку и установочный резерв; не откатывать базу ради конфигурации |

В итоговом протоколе своей установки отдельно отметьте: проверена поставка, установлено, подключено, проверены контроллеры, выполнена модельная работа, подтверждена сетевая доставка, проверено восстановление. Не объединяйте эти состояния в одно заявление «всё работает».
